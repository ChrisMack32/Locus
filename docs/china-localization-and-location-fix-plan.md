# Locus 简体中文、坐标偏移与手动收藏改进方案

日期：2026-10-18  
状态：方案与部分实现草稿；坐标偏移尚未通过真机验收。

## 1. 目标与已确认现象

本次改进覆盖三个需求：

1. 支持简体中文，包括主界面、设置、首次引导、错误提示、通知和系统权限说明。
2. 解决中国大陆选定地图 pin 后，点击 Teleport，实际位置移动但仍偏离目标几百米的问题。
3. 允许用户直接收藏地图手动选点，并在保存前填写名称。

用户已确认定位会移动，因此当前排查重点是坐标语义与转换链路。仍需确认观察位置的应用、设备系统版本、具体地点与原始经纬度；不能仅凭偏移量认定根因。

验收以“目标地点与接收端显示位置一致”为准，不能只看 Locus 的 Spoofing 状态或应用自己画出的模拟位置圆点。

## 2. 当前代码与问题边界

### 2.1 坐标传递

原始实现的主要链路如下：

```text
地图点选 MapProxy.convert / 搜索 MKLocalSearch / GPX 导入
    → session.pin 或路线坐标
    → SpoofSession.teleport / followRoute / tickJoystick
    → SpoofSession.apply
    → LocationEngine.set
    → idevice location_simulation_set
```

`startResend` 会直接调用 `LocationEngine.set`，因此只改 `teleport` 会漏掉定时重发；重连、路线和摇杆也必须遵守同一坐标约定。

原始代码没有坐标系标记，收藏只保存名称、纬度与经度。`apply` 在原生接口成功后，将请求坐标写入 `simulated`，这是请求成功的应用状态，不是从系统读取并验证后的实际位置。

### 2.2 收藏

原始实现已经支持地图上方的星标按钮，以及收藏列表中的重命名、删除。搜索结果会自动收藏。

主要不足是手动选点的保存入口不明显、缺少保存前的命名确认。本次复用 `SpoofSession.addFavorite` 与现有本地持久化，不另建收藏存储。

### 2.3 语言

界面大量使用英文字符串，部分字符串经普通 `String` 属性、条件表达式和错误对象传递。仅翻译 SwiftUI 的静态 `Text` 不足以覆盖这些路径。

## 3. 坐标偏移：先确认方向，再实施补偿

### 3.1 不能把“开启 WGS-84 → GCJ-02”当作通用修复

Apple 将 `CLLocationCoordinate2D` 定义为 WGS 84 参考系下的经纬度；这个 API 约定应作为默认基线，不能因为设备位于中国大陆，就假定所有 MapKit 返回值都是 GCJ-02。[Apple 官方文档](https://developer.apple.com/documentation/corelocation/cllocationcoordinate2d)

百度地图使用 BD-09，直接叠加其他坐标系的数值会导致显示偏移，使用其地图或服务时应遵循具体接口要求。[百度坐标系说明](https://lbsyun.baidu.com/skins/MySkin/resources/iframs/coordinate.html)

因此，应区分“地图显示需要转换”和“注入系统 GPS 需要转换”。如果输入已经是 GCJ-02，而定位注入端按 WGS-84 解释，应验证 **GCJ-02 → WGS-84**；再做一次正向转换可能加重偏移。反过来，只有接收接口明确需要 GCJ-02 或 BD-09 时，才选择对应正向转换。

此处是工程判断，尚未证明当前设备上的 MapKit 或 idevice 属于哪种情况。

### 3.2 排查顺序与可证伪假设

| 顺序 | 假设 | 验证方法与判定 |
| --- | --- | --- |
| 1 | 输入与注入端的坐标系不一致 | 对同一地标记录 pin、发送值和接收值；比较关闭转换与明确方向的转换。只有对应变换稳定消除偏移，才支持该假设。 |
| 2 | 接收端地图重复转换或显示坐标系不同 | 保持注入值不变，对比 Core Location 原始值与地图显示。若原始值正确而只有特定地图偏移，修正其显示边界，不全局修改 GPS。 |
| 3 | 地图触点换算造成标记坐标错误 | 同一地标分别通过搜索和手动点选；改变缩放、俯仰后复测。若误差随视角变化，检查 MapReader 坐标空间与布局。 |
| 4 | 路线、摇杆或旧会话更新覆盖新位置 | 停止其他移动任务后重试，观察首次定位及 8 秒重发后的结果。若首次正确、随后改变，检查任务竞争与重发路径。 |

在调试版本中查看输入、转换模式、最终发送值及时间即可。真实位置数据仅本地查看，不提交仓库；无需打印配对文件或凭据。

### 3.3 设置与转换入口

第一阶段提供显式设置，默认关闭，不按系统语言或地区自动启用：

| 选项 | 用途 |
| --- | --- |
| 关闭（原始坐标） | 保持当前行为，也是对照组。 |
| WGS-84 → GCJ-02 | 接收端明确要求 GCJ-02 时使用。 |
| WGS-84 → BD-09 | 接收端明确要求 BD-09 经纬度时使用。 |
| GCJ-02 → WGS-84 | 经验证输入为 GCJ-02、注入端需要 WGS-84 时使用。 |

在 `LocationEngine.set` 处执行一次转换，让普通定位、路线、摇杆、重发和重连共用该入口。转换后的值只交给 FFI，不能回写到 `session.pin`、`session.simulated`、收藏或路线，防止下一次调用再次转换。

切换前停止当前模拟会话；界面需说明选项是坐标解释方式，不保证对所有地图都有效。

### 3.4 第一阶段方案的限制与后续决策

全局转换设置适合单一来源的诊断与兼容场景，**不能可靠区分混合来源**。例如地图选点若经验证为 GCJ-02，而导入 GPX 为 WGS-84，统一执行逆转换会使 GPX 出错。

正式发布前必须验证地图点选、搜索、道路路线、GPX 和真实 GPS 的来源语义：

- 如果所有入口都遵循 WGS-84，则保持默认直通，定位具体显示端或服务问题。
- 如果确认存在不同坐标系输入，则在来源边界归一化为 WGS-84，后续业务状态、收藏、路线与定位注入统一使用 WGS-84。
- 只有明确需要其他坐标系的外部显示或导出边界才做正向转换；不因用户在百度地图中观察位置，就直接改变系统 GPS 的坐标系。
- 实施来源归一化后，取消普通流程中的全局补偿，避免入口和出口同时转换。
- 旧收藏没有坐标系信息，保留原始数据，不自动批量转换；确需迁移时增加版本或来源字段，并提供兼容读取与明确的迁移策略。

不要同时引入一套全局补偿和一套来源补偿作为默认行为。先用真机证据确定正式发布的路径。

### 3.5 算法与范围

使用无网络依赖的纯函数，输入为坐标与转换模式，输出为新坐标。支持 GCJ-02 正向近似、迭代逆变换，以及 GCJ-02 到 BD-09 的组合转换。

校验经纬度有限且有效；关闭模式保持输入不变。当前草稿使用经度 `72.004–137.8347`、纬度 `0.8293–55.8271` 的近似矩形范围，范围外不转换。

该矩形不是中国大陆行政边界，会包含部分周边地区，不能用于宣称“精确自动识别大陆”。第一阶段保持手动选择并说明限制；需要自动识别时另行评估准确的覆盖数据。

## 4. 简体中文方案

使用 iOS 原生本地化：英文 `en.lproj`，简体中文 `zh-Hans.lproj`，覆盖用户提出的 `zh-CN` 使用场景。默认跟随系统或应用语言，保留英文回退。

覆盖范围：

- 地图搜索、底部操作、状态栏、路线和摇杆的可访问性标签。
- 设置、收藏、最近记录、命名弹窗和首次设置引导。
- 配对提示、定位错误与本地通知。
- `InfoPlist.strings` 中的位置与本地网络权限说明。

动态文案使用 `String(localized:)`；插值文案保留格式占位符，避免拼接已翻译片段。地点名称、用户填写的名称、坐标数值、IP、文件名、持久化键和网络协议字段不翻译。

项目的 `developmentLanguage` 与资源引用通过 `project.yml` 和 XcodeGen 管理。英文、中文的键集与格式占位符须一致。中文在小屏幕、较大字体和长错误提示下不能遮挡主要操作。

## 5. 手动收藏方案

交互流程：

```text
轻点地图放置 pin
    → 点击 pin 的“收藏此位置”，或地图上方星标
    → 弹出名称输入框
    → 保存 / 取消
    → 在“地点 → 收藏”中查看
```

具体行为：

- 打开弹窗时固定本次待保存的坐标，避免后台会话更新后保存到其他位置。
- 搜索得到的 pin 优先带入地点名称；普通选点使用已有名称或经纬度作为建议。
- 拖动 pin 后清除旧搜索名称，避免新位置沿用不相关名称。
- 名称为空时使用经纬度；取消不写入；相同坐标沿用现有去重逻辑。
- 保存不需要已配对或已开启模拟定位，重启后可读取。
- 保留现有搜索自动收藏行为，避免将交互改动扩展到未提出的需求。

## 7. 实施顺序与完成标准

1. **建立真机对照**：选取已知地标，记录关闭转换时的偏移，明确观察端与输入来源。完成标准是能重复定位并测量同一误差。
2. **确定正确坐标边界**：对照正向、逆向及不转换的结果，核对重发与不同来源。完成标准是能解释每一处转换，且相同点不会重复偏移。
3. **完成三项功能**：补齐原生本地化、明确转换设置和手动收藏交互。混合来源存在差异时，先实施第 3.4 节的归一化再发布。
4. **验证并交付**：通过下方自动检查和真机验收，记录适用系统、模式与尚存限制。

## 8. 验证计划

### 8.1 自动检查

- 北京参考点的 GCJ-02、BD-09 输出符合预期；北京、上海、深圳正逆转换误差在数值容差内。
- 关闭模式及范围外坐标不变；重复发送从原始逻辑坐标计算，不累加偏移。
- 增补经纬度非法值、边界点、异常设置值回退检查。
- 本地化资源可解析，键集、格式占位符一致；动态错误与通知也通过本地化路径。
- 工程成功生成，完成不签名设备构建。

```sh
xcrun swiftc -module-cache-path /tmp/locus-swift-module-cache \
  Locus/Engine/CoordinateTransform.swift Tests/CoordinateTransformChecks.swift \

/tmp/locus-coordinate-checks
```

### 8.2 真机验收矩阵

| 场景 | 预期 |
| --- | --- |
| 大陆地标，手动选 pin → Teleport | 接收端到达目标；消除原有几百米系统性偏移。 |
| 同一地标，搜索 → Teleport | 与手动选点结果一致。 |
| 定位后等待至少 30 秒 | 重发后位置不跳回，也不叠加偏移。 |
| 摇杆、道路路线、手绘路径 | 移动连续，不因转换产生整体跳变。 |
| 标准 WGS-84 GPX 与真实 GPS 起点 | 保持原始地理位置，不受其他来源补偿误伤。 |
| 收藏后重启、重新定位 | 保存位置与原选点一致，名称和去重正确。 |
| 转换关闭、范围外地点 | 原有行为保持不变。 |
| 简体中文 / 英文 | 主流程、错误、通知与权限说明使用对应语言。 |
| 停止、重新连接、切换转换选项 | 状态明确，不残留旧模式下的重复更新。 |

建议将可靠地标参考位置与实际位置相差不超过约 20 米作为产品验收目标，结合地图标注误差判断。这是待验证目标，不是离线近似算法的精度承诺。
